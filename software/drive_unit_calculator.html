How to use this

Enter the numbers for each axis built. The calculator then renders the same result three ways.

The normal path is the config.ini below. Save it as Marlin/config.ini and build. Marlin's own pre-build script reads it and applies every setting to the two configuration headers, including the ones that must end up commented out. Nothing is typed by hand and nothing can be missed.

The Marlin subfolder, not the project root It goes beside Configuration.h, not beside platformio.ini. The root looks like the obvious place and is wrong: platformio.ini declares the file under extra_configs as Marlin/config.ini. Put it in the root and nothing reads it, nothing errors, and the build silently uses the stock settings.
Replace the shipped file, do not add to it Marlin already ships a Marlin/config.ini, around ten kilobytes of commented reference, and line 44 of it reads ini_use_config = none, which Marlin documents as "ignore this file and don't apply any configuration options". Paste the block below into that file instead of replacing it and nothing applies: the build succeeds, no warning appears, and the firmware carries stock settings.
Freezing it later The emitted file carries a commented ini_use_config = none of its own. Uncomment it once the machine is tuned and the headers hold the values worth keeping. That stops this file re-applying on every build, so hand edits to Configuration.h survive. The cycle is: generate, build, flash, tune on the bench with M203 and M500, write the proven numbers back into this page, regenerate, then freeze. Leave it commented while this page is still the source of truth.
First build on a fresh tree Name the build environment explicitly the first time, for example platformio run --environment STM32F446ZE_btt. Auto Build Marlin decides which environments to offer by reading MOTHERBOARD from Configuration.h, and on a fresh tree nothing has applied this file yet, so it offers the stock board's environment instead. After one build it detects correctly.

The two blocks under it are the manual fallback, for a build that does not go through PlatformIO. Neither is a complete file and neither replaces one: each is a list of defines to change inside a stock Marlin header of several thousand lines.

The ini edits in place config.ini rewrites Configuration.h and Configuration_adv.h on disk at every build, and it never reverts. Removing a line from the ini later does not undo the edit it already made. It removes transcription errors, not the need to know what state the tree is in.

Every value here is a starting point for testing, not a tuned result: measure on the bench and write the measured values back.

Controller board

Any board Marlin supports works here. The name is emitted as typed and is not checked against a list, because the authoritative set is the tree being built, not this page. A wrong name fails the build with a clear message, which is the right way for it to fail.

Finding the constant The definitive list is Marlin/src/core/boards.h in the Marlin folder being built. It matches that version exactly, needs no network, and is what Marlin's own documentation points at: "The boards.h file has the most up-to-date listing of supported boards." The same guidance online is at marlinfw.org/docs/configuration/configuration.html under Motherboard.
Pins are board-specific Two blocks below carry pin numbers rather than settings: the second Z endstop for gantry squaring, and the six pins for a rotary I axis, which Marlin's board files do not map. Those numbers are Octopus V1.1 pins. Naming any other board suppresses both blocks and emits instructions in their place, rather than handing over pin numbers that would be wrong.
Motion defaults

One machine-wide figure, emitted as DEFAULT_ACCELERATION and DEFAULT_TRAVEL_ACCELERATION. Marlin holds these as single values, not per axis. Each axis carries its own ceiling separately, as DEFAULT_MAX_ACCELERATION.

This number governs more than it appears to It sets the stroke each speed needs, and therefore the automatic speed ceiling on every axis. At 500 a 220 mm axis tops out near 230 mm/s; at 2000 the same axis reaches 460. A value left at the default on a machine capable of more produces a ceiling that looks derived and is low.
Why this one is not calculated Speed follows from stroke and acceleration, both of which are known here. Acceleration follows from motor torque, moving mass and the gearset ratio, and mass is not an input. Entering a guess and correcting it on the bench is honest; deriving it from a mass that was also guessed is not. Raise it in steps and watch for skipped steps under load.

Auto suits a linear axis better than a rotary one The automatic ceiling comes from the stroke, on the reasoning that a carriage has to accelerate to a speed and then brake before it runs out of travel. An axis that turns continuously never reaches an end, so that reasoning does not bind and the figure it produces is not a real limit. For a rotary axis the ceiling that matters is the motor's, so set it by hand.

Speed ladders

A rung has to clear two separate limits. The stroke must be long enough to reach the commanded speed before the carriage has to slow down again, and the speed must sit within the emitted maximum feedrate or Marlin refuses the command before the axis moves at all. Rungs are marked against both.

Profile for the operator panel

Download this file and import it in the operator panel, under Commission, then Calculator profile. The panel compares the steps per mm predicted here against what the board reports at every connect, and reports when the flashed firmware does not match the machine described here.

What this calculator assumes

Three items remain assumptions. Everything else it emits is either computed from the entered values or established by measurement.

Endstop polarity Comes from the selection made here, and that selection is only correct if the pin was measured. Probe the signal pin at rest and at trigger; do not infer it from the switch type. Confirm with M119 after flashing in every case.
Sense resistor RSENSE is taken from the driver module named here. A module that differs from the standard part carries a different sense resistor, and a wrong value rescales every commanded current. Confirm it against the product page for the module fitted.
Rotary I axis pin block Written for the MOTOR4 / E0 slot. Marlin's board file maps no I axis, so the pins are stated explicitly. Moving the axis to another slot means editing those six lines by hand.

Currents, feedrates and accelerations are starting values for testing, deliberately set below what the hardware may prove capable of. The steps per mm figure is exact arithmetic from the gearset, so a measured deviation means a mechanical fault or the wrong gearset entered, never a rounding error.

Arithmetic

steps/mm = full steps × microsteps × (gearset teeth ÷ 20) ÷ 40
rotary steps/degree = full steps × microsteps × (teeth ÷ 20) ÷ 360
run current = 0.7 × rated phase current, rounded to the nearest 50 mA, then clamped to the driver's sustained rating
stroke needed = 2v² ÷ a, at a = 500 mm/s²
